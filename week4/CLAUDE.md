# CLAUDE.md

Base58 (Bitcoin alphabet) encode/decode, published to npm as `base-58`. One CoffeeScript source file that works both as a Node module and as a browser global (`window.Base58`). No runtime dependencies.

## Architecture

- `Base58.coffee`: the only library source. Its first line, `Base58 = (module?.exports) or (window.Base58 = {})`, is what makes it dual Node/browser; keep it.
- `Base58.js`: compiled from `Base58.coffee` and **committed** (it's `main` in `package.json` and the file the README tells browser users to download).
- `Base58_Test.coffee`: shared tape tests, exported as `(tape, Base58) ->`. Run by `Base58.node.test.coffee` (Node) and `Base58.window.test.coffee` (browser, via `window_test_harness.coffee` + `window.html`).
- `test/bs58.js` + `test/fixtures.json`: separate mocha suite, kept for compatibility with the original `cryptocoinjs/bs58` package.

## Commands

```sh
npm install
npx coffee --compile Base58.coffee   # regenerate Base58.js; run after every source edit
npx mocha                            # mocha suite in test/ (33 tests)
npx coffee Base58.node.test.coffee   # tape suite (35 assertions)
```

- `npm test` only works in a POSIX shell: every script chains steps with `;`. On Windows (cmd.exe) it fails with `Missing script: "bs58.compatibility.test;"`. Run the commands above instead, or `npm test --script-shell="C:\Program Files\Git\bin\bash.exe"`.
- Browser tests: `npx coffee --compile window_test_harness.coffee Base58_Test.coffee Base58.window.test.coffee`, then `npx browserify Base58.window.test.js > window.js`, then open `window.html` (`open` on macOS, `start` on Windows). They need a human to look at the page; don't treat them as a check you can run yourself.
- There is no linter or formatter.

## Conventions

- CoffeeScript 1.x (`coffee-script` 1.x, currently 1.12.7). Match the existing style: `is`/`isnt`/`unless`, explicit `while` loops with index counters (code was converted from JS by Js2coffee), no ES2015+ syntax, since the compiled output must run in old browsers.
- Invalid input throws a **string**, not an `Error`: `"Base58.decode received unacceptable input. ..."`. Both test suites match it with `/decode received unacceptable input/`; keep that prefix.
- `decode` returns `new (Uint8Array ? Buffer)(...)`, so it returns a `Uint8Array` on modern Node. The README's "returns a Buffer" claim is out of date.
- Test fixtures are duplicated: inline `FIXTURES` at the bottom of `Base58_Test.coffee`, and `test/fixtures.json`. Add or change a case in **both**.
- Tape tests use `test.plan FIXTURES.valid.length` and `test.same`; a new loop-over-fixtures test needs a matching `plan`.

## Guardrails

- Never hand-edit `Base58.js`. Edit `Base58.coffee`, recompile, and commit both.
- Recompiling rewrites line 1 of `Base58.js` from `// Generated by CoffeeScript 1.8.0` to `1.12.7` even with no source change. If you didn't change `Base58.coffee`, `git checkout -- Base58.js` before committing.
- Don't commit test build output (already gitignored): `Base58_Test.js`, `Base58.*.test.js`, `window.js`, `window_test_harness.js`.
- Don't add runtime dependencies. `mochify` in devDependencies is unused; leave it rather than wiring it in.
- `package.json` `repository` points at upstream `45678/Base58`; don't change it unless asked.
